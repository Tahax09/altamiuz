# Threat Model: CMS Content Editing (US2, T094)

Scope: `pages`, `services`, `courses` and `redirects` through the admin, REST and the Local API.
Authentication, MFA and sessions are covered in `TM-auth.md`. Evidence lives in
`tests/integration/content/*.test.ts`, `tests/unit/content/*.test.ts` and
`tests/security/content-http.spec.ts`.

Findings recorded during WS9 (Payload 3.91.0):

1. A non-draft `restoreVersion` overwrites the live document, and the Local API drops `draft`.
   Mitigated (ADR-006).
2. Every save deletes the document lock, so autosave defeats locking. Mitigated: autosave is off.
3. Malformed Lexical `children` caused a 500 inside `@payloadcms/richtext-lexical` hooks.
   Mitigated by the early structural check.
4. REST ids with a numeric prefix are coerced (`"1 OR 1=1"` → `1`). The query stays
   parameterised and access still applies, so this is informational.
5. A failed save under load can show only the error toast, without inline field errors.
   `ErrorFocus` also maps the toast's field list, so focus and `aria-invalid` still work.

Residual risks:

- The rich-text policy covers the v1 feature set only. Each new editor feature needs a policy
  bump and corpus cases.
- Admin-side (Payload core) accessibility findings remain. See
  `docs/accessibility/admin-findings.md`.
