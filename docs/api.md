# HTTP Interface Inventory (FR-096, T140)

Every HTTP interface the application exposes. The public site itself uses no HTTP API: it reads
through Payload's Local API on the server (ADR-002). The inventory below is **generated** from the
sanitized Payload configuration and the App Router route handlers by `pnpm docs:api`, and
`tests/unit/docs/api-docs.test.ts` fails CI when it no longer matches the code.

How to read it:

- **Auth and access**: every collection/global endpoint applies that collection's access rules;
  CMS access needs a session with completed MFA (`docs/security/TM-auth.md`, access matrix in
  `src/modules/access`). Exceptions and the full semantics (request/response shapes, rate limits,
  bearer tokens for `/api/health/ready` and `/api/jobs/*`, CSRF/origin rules) are in
  `specs/001-v1-website-cms/contracts/http-surface.md`.
- **Blocked**: Payload built-ins replaced by project flows; the proxy answers 404 before Payload.
- **Payload built-in** endpoints exist on every collection; many are refused by access control
  (e.g. create/update on `enquiries` and `audit-events`; Payload's job endpoints `run`,
  `queue`, `cancel` are closed in `jobs.access`).
- Public interfaces for integrations: none in v1 besides the health and scheduler endpoints.
