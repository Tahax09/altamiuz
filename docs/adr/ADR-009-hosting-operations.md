# ADR-009: Production hosting and operations architecture (US8, T132–T136)

- **Status**: Accepted (2026-11-07). Hosting choice approved by the owner: **Vercel** (application),
  **Neon PostgreSQL** (database), **Cloudflare R2** (media and off-site backups). This ADR records
  the operational architecture; it does not reopen the choice. No account was created, provisioned
  or changed while writing it.
- **Supersedes**: the "production host undecided" notes in plan.md, `docs/runbooks/cache.md` (L-3
  multi-instance caveat) and `src/modules/platform/cache.ts`.

## Architecture

| Concern              | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Enforced / verified by                                                                                      |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Plan                 | Vercel **Pro** (Hobby is non-commercial and limits cron to once a day; the enquiry scheduler needs every minute).                                                                                                                                                                                                                                                                                                                                                               | Owner action O-1                                                                                            |
| Database connections | Runtime `DATABASE_URL` = Neon **pooled** endpoint (`-pooler` host, PgBouncer transaction mode). Migrations and backups use the **direct** endpoint (session features, `pg_dump`). TLS required (`sslmode=require` or `verify-full`) for any non-loopback host.                                                                                                                                                                                                                  | `loadConfig` refuses production without sslmode; `scripts/with-neon.mjs` refuses pooled URLs for migrations |
| Migrations           | Never at build or boot. `pnpm migrate` against the direct URL **before** promoting a deployment, expand-then-contract only (docs/runbooks/migration.md). Schema push is refused outside development/test.                                                                                                                                                                                                                                                                       | `DATABASE_ALLOW_PUSH` guard; runbook                                                                        |
| Persistent media     | Vercel's filesystem is ephemeral, so media must live in R2. Production refuses `STORAGE_DRIVER=local`. The S3/R2 adapter (`@payloadcms/storage-s3`, new dependency) is **not implemented**; until it is, production cannot boot (`mediaStaticDir()` throws) and readiness reports `storage: fail`.                                                                                                                                                                              | config test, `tests/integration/ops/observability.test.ts`; owner action O-3                                |
| Upload size          | Vercel Functions accept request bodies up to 4.5 MB; A-7 allows 20 MB uploads. Larger uploads will fail on Vercel until uploads go direct to R2 (presigned, client-side upload in the storage adapter) or A-7 is lowered.                                                                                                                                                                                                                                                       | Owner decision O-4                                                                                          |
| Cache invalidation   | Public reads use `unstable_cache` with tags; writes call `revalidateTag(tag, { expire: 0 })`. On Vercel the Data Cache is shared by all function instances, so the per-process caveat of a self-hosted multi-instance setup does not apply. **To verify on the first preview deployment** (SC-009 re-test), not assumed.                                                                                                                                                        | Next stage: preview verification                                                                            |
| Rate limiting        | `RATELIMIT_DRIVER=postgres` (Neon): one atomic upsert per hit, shared by every instance; fails closed. Client IP: Vercel overwrites `X-Forwarded-For`/`X-Real-IP` with the connecting client, so set `CLIENT_IP_HEADER=x-real-ip` when Vercel is the edge. If Cloudflare is put in front of Vercel, the header and a bypass-proof origin are a separate decision (O-5).                                                                                                         | production config requires a client-IP source                                                               |
| Scheduler            | Vercel Cron (`vercel.json`): `GET /api/jobs/run` every minute (enquiry notifications and retries), `GET /api/jobs/retention` daily 03:17 UTC (enquiries 12 months, audit 24 months, ended rate-limit windows). Vercel sends `Authorization: Bearer $CRON_SECRET`; `CRON_SECRET` is set to the same value as `JOBS_SIGNING_SECRET`. Production refuses `JOBS_TRIGGER=local-runner` (no long-running process).                                                                    | integration: wrong/missing signatures → 401 on GET and POST; config test                                    |
| Email                | Provider-neutral boundary: production `EMAIL_DRIVER=smtp` only with `smtps://user:pass@host:465` to a non-local host (any provider's SMTP relay). `resend` (HTTP API) stays a declared driver without an adapter; readiness reports `email: fail` if selected. Provider, sending domain and SPF/DKIM/DMARC are owner actions (O-6).                                                                                                                                             | config tests (plaintext, no credentials, loopback, placeholder refused)                                     |
| Health and alerting  | `/api/health` (liveness, public, no details) and `/api/health/ready` (bearer token) with checks `database`, `storage` (critical → `unavailable`) and `email`, `enquiryDelivery` (→ `degraded`), each with a 3 s timeout; any non-200 alerts. The delivery check reads the database, so it alerts even when the email provider or the log pipeline is the failing part. Abuse and failure events are structured JSON signal lines on stdout (`src/modules/platform/signals.ts`). | `tests/integration/ops/observability.test.ts`, docs/runbooks/monitoring.md                                  |
| Backups              | Neon point-in-time restore is a provider convenience, not the backup of record. Daily encrypted logical backups (`ops/backup/db.sh`, `ops/backup/media.sh`, age, public key only on the runner) by the scheduled workflow `.github/workflows/backup.yml` to a separate R2 bucket with a 30-day lifecycle rule and its own write-only token; heartbeat to the monitor on success.                                                                                                | `tests/integration/ops/backup.test.ts`, restore drill (docs/runbooks/restore.md)                            |
| Encryption at rest   | Backups: age (X25519), verified by the drill (no plaintext markers in artefacts). Neon and R2 encrypt stored data at rest per their documentation; that is a provider claim the owner verifies in each account (O-7), not something this repository can test.                                                                                                                                                                                                                   | drill report; owner action O-7                                                                              |

## Consequences

- Production deployment is blocked until O-3 (storage adapter), O-6 (email provider) and the other
  owner actions in docs/runbooks/deploy.md are done. Readiness reports both gaps by name.
- Recovery objectives (A-10) are met in a local drill (docs/runbooks/restore.md#evidence); the
  production RTO additionally depends on Neon and R2 transfer rates, to be measured in the first
  drill against a Neon branch.
- SC-010 measured locally at the production cadence (docs/runbooks/monitoring.md#sc-010); not a
  production guarantee until re-measured on the preview deployment with the chosen provider.

## Amendment 2026-11-18: Hobby test deployment

At the owner's request a **test** deployment runs on the Vercel Hobby team (non-commercial terms;
the owner accepted that for a test link). Differences from the architecture above, all to be
reverted on the Pro team before launch:

- `vercel.json` runs `/api/jobs/run` once a day (03:05 UTC) because Hobby allows daily cron only;
  enquiry notification retries are therefore delayed up to a day. Restore `* * * * *` on Pro.
- Media uses Vercel Blob (`STORAGE_DRIVER=vercel-blob`, `@payloadcms/storage-vercel-blob`) instead
  of R2, which is not built yet (O-3). Files are still served through `/api/media/file/…`.
- `APP_ENV=preview`: the site is not indexed (robots disallow) and production-only checks
  (route vocabulary CD-13, email provider) do not apply. Database: the Neon `dev` branch.
